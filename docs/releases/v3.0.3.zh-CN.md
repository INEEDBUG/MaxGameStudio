# MaxGameStudio 3.0.3

本版本重点重组英雄联盟功能入口，修复页面状态与 Mini 生命周期问题，并降低重复状态请求。CS2 与 VALORANT 仅保留兼容性调整，没有进行高风险重构。

## 英雄联盟信息架构

- 英雄联盟成为独立一级分区，自动化、战绩、玩家中心、实时对局和工具箱均可直接进入。
- 原 `/league-lab` 链接继续兼容，并保留查询参数后重定向到新的正式入口。
- 已稳定的战绩、玩家中心和实时对局不再藏在多层“实验室”标签中。
- 工具箱内部仍按用途分组，避免把所有高级功能堆在同一屏。

## 英雄联盟稳定性与交互

- 多个桌面辅助组件改为共享同一份 League 状态订阅，避免各自维护独立轮询器。
- 共享订阅具备请求合并、取消订阅和代次保护，卸载后的旧响应不会覆盖当前页面状态。
- Mini 原生窗口同步保留最后一份待处理状态，快速进入 `InProgress` 时不会因丢失隐藏事件而继续覆盖游戏。
- 自动化页将状态加载与战绩加载拆分，避免局部刷新阻塞整个页面。
- 玩家中心、实时对局和战绩详情补充竞态保护、空态与失败状态，并减少无效重渲染。

## 导航与模块边界

- CS2 功能统一到 `/cs2/*`，旧路径继续无损重定向。
- VALORANT 的真实拉伸与准心编辑器拥有独立直达入口。
- 灵敏度实验室和磁轴输入实验室移动到独立“外设调优”分区，不再归属于 CS2。
- 侧栏分组会记住展开状态，并在进入对应页面时自动展开当前游戏分区。

## 性能优化

- 四个常驻 League 桌面管理器从各自轮询改为共享 1.5 秒状态源；按固定一分钟模型，请求次数由 60 次降至 40 次，减少约 33%。
- 实时对局嵌入页不再额外拉取一份相同状态；该页面额外状态请求由每分钟 12 次降为 0 次。
- 十名玩家的本地标签分析从每名玩家各读一次文件改为每轮只读一次，单轮由最多 10 次降为 1 次。
- 后端状态端点增加短时间请求合并，防止多个同时到达的读取触发重复 LCU 快照；事件或账号写入后立即失效，不缓存动作判断。

上述请求数为代码路径与定向测试可复现的固定轮询模型，不代表不同电脑上的网络延迟或内存绝对值。由于发布验收环境没有运行中的英雄联盟客户端，本版本未宣称完成真实 Lobby → ReadyCheck → ChampSelect → InProgress 全阶段实机基准。

## CS2 与 VALORANT

- CS2 保留 3.0.2 的 Demo 快速预览、低内存完整解析和回放延迟加载路径，本轮未做大范围改造。
- VALORANT 保持真实拉伸检测、1568×1080 社区预设和官方格式准心码编辑功能；只调整导航入口和页面分区。

## 兼容性与更新

- 旧的 CS2、League、VALORANT 与外设实验室 URL 继续可用并保留查询参数。
- 更新弹窗会用普通语言分列说明修复、新功能和优化；普通更新仍可选择暂不升级此版本，手动检查更新不受影响。
- 安装标识、签名公钥、更新端点与旧版迁移钩子保持不变，继续支持从 3.0.2 覆盖升级。

实际安装包、签名状态和发布状态以对应 GitHub Release 页面为准。
