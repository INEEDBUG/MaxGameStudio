# MaxGameStudio 3.1.0

> **正式稳定版。** `v3.1.0` 是 `v3.0.5` 的直接后继版本，并取代了从未发布的内部候选 `v3.0.6`。本版本已经完成本机安装、真实对局与管理员启动验收；正式安装包仍以 GitHub Release 中由稳定版 CI 生成和签名的文件为准。

## 单一内嵌英雄联盟工作台

- 英雄联盟入口收敛为由 MaxGameStudio Tauri 宿主管理的单一工作台。
- 工作台从固定的 `v1.5.1` 源码构建，固定提交为 `14557723706ccc0e0a9d62c470141d4cb7190fcd`，并作为桌面资源内嵌。
- 宿主负责工作台的启动、停止与更新边界；内嵌运行时的独立更新路径已禁用，避免与 MaxGameStudio 的更新边界混淆。
- 产品界面使用 MaxGameStudio 品牌，不把源项目作为独立产品入口或宣传对象；原始 MIT 版权与许可证归属仍完整保留。

## 启动方式

- **每次询问**：手动进入 `/league` 时始终先选择本次启动方式，不会因为已有记忆而静默启动或切换。
- **节省内存**：启动前暂停 MaxGameStudio 后端及 CS2/无畏契约后台任务，销毁主 WebView，只保留轻量 Tauri 守护进程和内嵌工作台；工作台退出后恢复主窗口和后端。
- **后台并行**：保留 MaxGameStudio 主窗口、主 WebView、后端及后台任务，与工作台并行运行。该模式可能占用更多内存，启动前会显示本机实测参考值，实际占用仍会随页面和系统变化。
- **可逆自动进入**：工作台入口和“设置 → 系统与更新”都可以记住“节省内存 / 后台并行”选择；记住后只会在检测到英雄联盟客户端时自动进入。手动进入 `/league` 时仍会显示选择界面，记住的模式只作为预选项；主动退出工作台后，同一次客户端会话不会循环重开，也可以清除选择并恢复为每次询问。
- **可选管理员启动**：可以只为内嵌英雄联盟工作台请求管理员权限，不会提升整个 MaxGameStudio。管理员选择可以随“节省内存 / 后台并行”一起记住，但自动进入仍只在检测到客户端时发生；Windows 会按权限策略显示 UAC，取消授权不会关闭主窗口或后端，也不会把取消操作记成成功记忆。普通宿主先校验安装载荷；获准后由 Windows 受保护的系统 PowerShell 把清单内文件复制到同一磁盘的随机隔离会话，提权侧再次绑定清单摘要、逐文件复核 SHA-256、拒绝重解析点与额外文件，并在整个运行期间锁住目录和载荷。管理员工作台改用同一磁盘上的独立受保护 Chromium 配置，不再直接从用户可写的安装目录或普通用户配置加载提权内容。

## 界面与工具边界

- **双主题按钮可见性**：修复浅色和深色主题下主题按钮文字、图标与边框对比度不足而难以辨认的问题。
- **侧栏红线**：清理侧栏遗留的红色边线，避免导航出现与当前状态无关的错误提示感。
- **League 工作台图标**：新增独立的 League 工作台图标，便于在系统窗口和内嵌工作台资源中识别它。
- **移除游戏内发送**：删除旧的 League 游戏内发送入口，不再将 Game Send 作为当前可用功能宣传；合法的上游 MIT 版权与许可证归属仍保留。
- **安全升级保护**：升级前会等待内嵌英雄联盟工作台退出；若工作台仍在运行则中止安装，不会强制关闭或覆盖正在使用的运行时。管理员会话使用独立受保护副本，正常退出后由提权启动器在复核路径和重解析点后清理临时会话；长期配置仍保留在同一磁盘的受保护配置目录。
- **发布签名边界**：Tauri 更新签名仍是正式更新通道的强制条件，Windows Authenticode 与其相互独立。仓库配置 PFX 时，CI 会签名内嵌工作台、主程序和安装包并刷新清单；未配置时仍沿用此前流程发布不带 Authenticode 的安装包，Windows 可能显示“未知发布者”，但清单、SHA-256、受保护管理员会话和 Tauri 更新签名仍然生效。

## 版本与升级边界

- 项目元数据统一为 `3.1.0`；内嵌英雄联盟运行时固定为上游 `v1.5.1` 源码提交，二者属于不同版本边界。
- `v3.0.6` 从未进入 GitHub Release 或正式更新通道；现有 `v3.0.5` 用户会直接收到 `v3.1.0` 更新，不需要安装中间版本。
- 本地未签名候选只用于验收，不作为正式分发文件。正式用户应以 GitHub Release 与签名更新通道提供的安装包为准。
